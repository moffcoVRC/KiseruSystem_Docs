# 診断ログの保存とエラーの報告

導入時に問題が起きた場合は、**診断ログ**を保存すると、確認に必要な状態をまとめられます。ログは自動送信されません。

## 診断ログを作成して保存する

1. エラー時に現れるオレンジ色の**診断ログを作成して保存**を押します。
2. 必要であれば、**アバター製品名（任意）**を入力します。空欄でも保存できます。
3. **診断ログを作成・更新**を押します。
4. 表示されたJSONの内容を確認します。
5. **保存先を選んで診断ログを保存…**を押し、保存先を選びます。

通常の画面から開けない場合は、Unityの上部メニューの**Tools → Mofcosmos → Kiseru → 診断ログを作成して保存**から開くこともできます。

アバター製品名には、本名・ユーザー名・連絡先を入力しないでください。

## 記録する情報

- Unityのバージョンとコンパイル状態
- VRChat SDK、Modular Avatar、NDMF、lilToonなどの必要なパッケージの状態
- 必要アセットの有無、Humanoid、取付ボーン、参照の不備
- パラメーター容量・型の競合、導入データの構成
- 例外の種類や、製品コード内の発生箇所など

取得できるエラー履歴は、記録開始後の**最近30分・最大64件**です。過去のEditor.logを読み戻すものではありません。検出結果は原因の候補であり、すべての他製品との競合やVR実機の問題を自動判定できるわけではありません。

## 自動では記録しない情報

アバター名、PC名、絶対パス、アカウントやBlueprintのID、Sceneやオブジェクトの名前、Console原文は自動で記録しません。欠落アセットの特定には、製品内で決まっている相対パスを使います。

任意欄へ入力したアバター製品名は記録されます。内容を確認してから、必要な相手へログを共有してください。

## コンパイルエラーで画面が開けない場合 {#compile-errors}

Unityが診断用の拡張自体を読み込めない場合は、診断ログを生成できません。その場合はConsoleのエラーを伝えます。

1. Unityの**Console**を開きます。
2. **先頭にある赤いエラー**を選択します。
3. 詳細をコピーします。
4. **エラーコード・ファイル名・行番号**を残し、パスに含まれるPCのユーザー名などは伏せます。

例：`Assets/…/Example.cs(12,3): error CSxxxx: …`

## 問い合わせに添えること

- 使っている煙管システムのバージョン
- どの操作をしたときに、何が起きたか
- 再現できる場合は、その手順
- 保存できた診断ログ、または最初の赤いConsoleエラー
- 任意でアバターの製品名

症状が分かるよう、期待した動きと実際の動きを書き分けてください。公開される場所へ添付する場合は、個人情報が入っていないか、送信前に確認します。
